# Инструкция по запуску проекта

Кратко: три микросервиса (**Producer**, **Consumer**, **Telegram**) и инфраструктура (**RabbitMQ**, при необходимости **Redis**) в монорепозитории на **Node.js** и **Nest.js**. Ниже — два рабочих сценария: через **Docker Compose** (удобнее для демонстрации) и **локально** (удобнее для разработки).

---

## 1. Что должно быть на машине

| Требование | Версия / примечание |
|------------|---------------------|
| **Node.js** | 18 или новее |
| **npm** | 9+ (поддержка `workspaces`) |
| **Docker** и **Docker Compose** | для варианта с Compose и/или для контейнера RabbitMQ |
| **Git** | для клонирования репозитория |

Рекомендация для Windows: держать проект в пути **без кириллицы** (например `C:\work\notification-microservices`), чтобы не ловить редкие сбои npm и инструментов.

---

## 2. Получение кода и файла настроек

В каталоге, куда клонировали репозиторий (корень — там лежат `package.json`, `apps/`, `docker-compose.yml`):

```bash
git clone <URL-репозитория> .
# или распакуйте архив и перейдите в корень проекта
```

Создайте файл **`.env`** из шаблона:

```bash
cp .env.example .env
```

В Windows (PowerShell):

```powershell
Copy-Item .env.example .env
```

Откройте **`.env`** в редакторе и заполните **обязательно**:

- **`TELEGRAM_BOT_TOKEN`** — токен бота от [@BotFather](https://t.me/BotFather).
- **`TELEGRAM_CHAT_ID`** — **числовой** ID чата или пользователя (после нажатия **Start** у вашего бота). Это не телефон и не `@username` в этом поле. Узнать ID: [@userinfobot](https://t.me/userinfobot) или `getUpdates` в Bot API.

Остальные переменные в `.env.example` прокомментированы — их можно не трогать до появления проблем с сетью (см. раздел 6).

Установите зависимости и соберите проект:

```bash
npm install
npm run build
```

(Отдельно контракты: `npm run build -w @notification/contracts` — уже входит в полную сборку корня.)

## 3. Вариант A — запуск через Docker Compose (рекомендуется)

Подходит, когда нужно поднять **все сервисы одной командой**.

1. Убедитесь, что в корне проекта есть заполненный **`.env`** (см. п. 2).
2. В корне выполните:

```bash
docker compose up --build
```

3. Дождитесь готовности контейнеров. По умолчанию доступны:

| Что | Адрес |
|-----|--------|
| Producer API и Swagger | http://localhost:3001/api/docs |
| Consumer (health) и Swagger | http://localhost:3002/health , http://localhost:3002/api/docs |
| Telegram-сервис и Swagger | http://localhost:3003/api/docs |
| RabbitMQ Management | http://localhost:15672 (логин/пароль из образа: обычно `guest` / `guest`) |
| Redis (если используется в compose) | localhost:6379 |

4. Проверка цепочки: отправьте событие в Producer (PowerShell, одна строка):

```powershell
curl.exe -X POST http://localhost:3001/events -H "Content-Type: application/json" -d "{\"type\":\"telegram.notify\",\"payload\":{\"text\":\"Проверка из Docker Compose\"}}"
```

Если токен и chat id верны и сеть до Telegram разрешена, сообщение придёт в чат. Остановка: в терминале с Compose — `Ctrl+C` или `docker compose down`.

## 4. Вариант B — локальный запуск (три процесса + RabbitMQ)

Подходит для отладки без пересборки всех образов.

### 4.1. RabbitMQ

Если RabbitMQ ещё не запущен, в отдельном терминале:

```bash
docker run -d --hostname rabbitmq --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management-alpine
```

Проверка: в `.env` должны быть `RABBITMQ_URL=amqp://guest:guest@localhost:5672` и одинаковая **`RABBITMQ_QUEUE`** у producer и consumer (по умолчанию в шаблоне уже так).

### 4.2. Три сервиса Nest

В **трёх** терминалах из **корня** репозитория (порядок желательно: сначала Telegram, затем Producer и Consumer):

**Терминал 1 — Telegram:**

```bash
npm run start:dev -w @notification/telegram
```

**Терминал 2 — Producer:**

```bash
npm run start:dev -w @notification/producer
```

**Терминал 3 — Consumer:**

```bash
npm run start:dev -w @notification/consumer
```

### 4.3. Проверка

- Откройте http://localhost:3002/health — ожидается JSON с `"status":"ok"`.
- Отправьте событие (PowerShell):

```powershell
curl.exe -X POST http://localhost:3001/events -H "Content-Type: application/json" -d '{"type":"telegram.notify","payload":{"text":"Проверка локального запуска"}}'
```

- Swagger: http://localhost:3001/api/docs , http://localhost:3003/api/docs , http://localhost:3002/api/docs .

## 5. Swagger (OpenAPI)

У всех трёх HTTP-приложений документация по пути **`/api/docs`** на соответствующем порту. Там можно выполнить «Try it out» для `POST /events` и `POST /notifications`.

Для **`POST /notifications`** поле **`chatId`** можно **не указывать** — тогда используется **`TELEGRAM_CHAT_ID`** из `.env`. Не подставляйте вручную примеры вроде чужого числового id из документации — для Telegram это будет «чужой» чат и возможна ошибка `chat not found`.

---

## 6. Если Telegram недоступен (таймаут, блокировка)

1. **VPN или прокси** — задайте в `.env` переменные из комментариев в `.env.example` (`TELEGRAM_HTTPS_PROXY` или набор `TELEGRAM_PROXY_*`).
2. **Только проверка API без реальной доставки в Telegram** — в `.env` для сервиса telegram задайте **`TELEGRAM_MOCK_SEND=true`** (подробности в основном README).

---

## 7. Redis (несколько экземпляров Consumer)

По умолчанию идемпотентность по `messageId` хранится **в памяти** процесса. Если нужно несколько реплик Consumer с общим учётом дубликатов, поднимите Redis и укажите **`REDIS_URL`** (см. `.env.example`). В **Docker Compose** Redis уже подключён к consumer.

## 8. Сборка и тесты (кратко)

Из корня репозитория:

```bash
npm run build          # все приложения
npm test               # unit-тесты по workspace
npm run test:e2e       # e2e там, где настроено в workspace
npm run test:integration   # интеграционные тесты consumer (нужен Docker; без Docker: SKIP_INTEGRATION=1)
```

Подробнее о переменных и архитектуре — в **README.md** в корне репозитория.

## 9. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| Consumer не забирает сообщения | Запущены ли RabbitMQ и Producer; совпадают ли `RABBITMQ_URL` и **`RABBITMQ_QUEUE`** в `.env` у обоих. |
| `chat not found` | `TELEGRAM_CHAT_ID` — ваш **числовой** id; у бота нажат **Start**; в Swagger не отправляйте фиктивный `chatId`. |
| `ETIMEDOUT` / нет связи с api.telegram.org | Прокси, VPN или `TELEGRAM_MOCK_SEND=true` для теста без сети. |
| Ошибки при `npm install` | Путь без не-ASCII символов; Node 18+. |
